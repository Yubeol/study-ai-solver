# PROJECT — ADsP 시험공부 RAG

## 현재 목표 (2026-09-29 기준, 아래 원문보다 우선)
- 과목: **ADsP**
- 과제 성격: "나만의 시험공부 RAG 시스템" 실습과제. 내 자료(강의노트·교재·개인노트 캡처)를 업로드하면 OCR → 청킹 → 임베딩 → 저장되고, 질문하면 시험 형식 제약에 맞춰 근거와 함께 답한다.
- 문제 사진 풀이는 질의 기능의 입력 방식 중 하나로 포함한다(질문 텍스트 또는 문제 이미지).
- 팀원 4명이 각자 개인적으로 진행한다. 공유하는 것은 DB 서버뿐이며, 나중에 공용 프론트로 결과를 확인할 수 있다(D-021로 변경: 각자 개인 프론트). 발표는 없다.
- 기간: 약 2주 (2026-09-29 ~ 10-11, 10-12 ~ 10-15 여유분). 가능한 한 전체 기능을 구현한다.

## 추가 기능 요구사항 (2026-09-30)
### 1. 오답노트
- 문제를 올릴 때 **내 답**과 **내가 그렇게 고른 이유**를 같이 입력한다.
- 흐름: 근거 검색 → 정답 풀이(근거 인용) → 내 이유와 근거를 비교해 어디서 틀렸는지 설명 → 틀린 유형 분류 → 오답노트 저장 → 같은 개념의 문제로 재질문
- 틀린 유형: 개념 혼동 / 문제 오독 / 계산 실수 / 암기 부족
- 개념 혼동은 청크의 `confusable_concepts`(혼동 개념 목록)를 이용해 "무엇과 헷갈렸는지"를 짚는다.
- 판정기 역할 추가: "내 이유가 근거와 일치하는가", "틀린 유형은 무엇인가"
- 저장 테이블은 mingyu_app에 둔다(이번에는 설계만, 마이그레이션은 구현 세션에서).

### 2. 품질 검수 도구
- 페이지별 HTML 보고서: 원본 이미지 위에 crop 영역·텍스트 영역 bbox를 그리고, crop 이미지·추출 텍스트·설명문을 나란히 보여준다.
- 이후 관리 화면(C)의 검수 탭으로 확장한다(`v_review_queue` 활용).

### 3. 시각자료 표시 원칙
- 화면에서는 그래프를 다시 그리지 않는다. **원본 crop 이미지 + 설명문**을 보여준다.
- 문제 속 그래프는 비전 LLM이 텍스트로 풀어낸 뒤 그 텍스트를 검색·판정에 쓴다(Jev는 이미지 입력 불가).

## 팀 교재 데이터 (`data/raw/adsp/`, gitignore, 2026-09-30)
- `pdf/`: 휴대폰으로 책을 찍은 스캔 PDF(텍스트 레이어 없음). 1과목 50장, 2과목 64장, 3과목 211장. 기울기·페이지 휨·그림자·배경이 같이 찍혀 있다.
  - 실제 파일명: `1과목.pdf`, `2과목.pdf`, `3과목.pdf` → 반입 시 `subject1~3.pdf`로 정리
- `team_text/`: 팀원이 추출한 페이지별 텍스트. 파일명에 인쇄 페이지 번호가 들어 있다(1과목 14~63p, 2과목 66~129p, 3과목 132~342p). zip 인코딩 문제로 파일명이 깨져 있다.
  - 실제 폴더: `과1`(49개), `과2`(64개), `과3`(210개) → 반입 시 `subject1~3/`으로 정리
- 1·3과목은 PDF 장 수가 텍스트 파일보다 1개 많다. 3과목 PDF 94~96장 = 인쇄 226~228쪽 확인. 전체 매핑은 반입 세션에서 실제로 확인한다.
- 텍스트에 머리말/쪽번호("1과목 데이터 이해 | 14")가 섞여 있다. "(★기출)", "5년간 출제 횟수", "학습목표" 표시는 `exam_clues`로 활용한다.
- 이 세 권은 팀 텍스트를 extract_text 결과로 쓴다(출처 표시). PaddleOCR은 새로 업로드하는 캡처용으로 뒤로 미룬다.

## 과제 요구사항 요약 (실습과제 슬라이드)
- 업로드: 과목 선택/생성, 자료 유형(강의노트/교재/개인노트), 이미지 다중 업로드(JPG/PNG, PDF 선택), 처리 상태(OCR/임베딩) 표시
- 저장: 과목 단위 분리, 청크마다 출처 메타데이터(과목, 자료유형, 파일명, 페이지/순서)
- 검색/답변: 질문 임베딩 → Top-K 검색 → 근거와 함께 LLM 답변. 근거 구간을 UI에 반드시 표시
- 환각 방지가 핵심 KPI. 자료에 없으면 "자료에서 확인 불가"
- LLM 제약: 기본 시험모드(자료 근거로만, 근거 제시, 추측 금지, 간결) + 학생 커스텀 제약(예: 정의→키워드→예시, 서술형 200자 이내, 비교표, 예상 문제 2개). 같은 질문도 제약에 따라 답 형식이 바뀐다. 제약 프리셋 저장·재사용
- 화면 3개: A. 자료 업로드 / B. 공부(질의) / C. 과목·자료 관리(목록, 삭제/재임베딩, 사용 로그)
- 주의: 저작권(개인 학습 목적, 외부 배포 금지), API 키는 .env, 개인정보 넣지 않기
- 성공 기준: 시험에 실제로 써 보고 실용성·효율성·미비점·단점을 스스로 평가한다

# 새 프로젝트: 학습 자료 기반 문제 풀이 AI (RAG + LLM + Jev)

## 나에 대해
- 류민규, 부트캠프 수강생. FastAPI, Django, Spring Boot, React, PostgreSQL(pgvector), Neo4j, Docker, Jenkins 경험 있음.
- 직전 프로젝트에서 뉴스·논문 RAG → 초안 생성 → React 프론트까지 만들었고, AWS DB에 보안 그룹으로 내 공인 IP를 등록해 접속하는 방식을 썼음.

## 프로젝트 목표
내가 공부하고 싶은 과목의 이론 자료(교재, 강의 노트, 개념 정리 등 공개 자료)를 수집·청크·임베딩해 DB에 저장하고,
사용자가 문제집 페이지나 문제 사진을 업로드하면 관련 이론을 검색해서 LLM이 근거와 함께 풀이를 제공하는 서비스.
- 풀이에는 어떤 이론 자료를 근거로 했는지 출처가 보여야 함 (근거 없는 풀이 금지).
- 과목은 아직 정하지 않음. 처음 설계는 과목에 의존하지 않게.

## Jev 사용 계획 (TypeSafe AI, 2026-09-15 얼리 액세스 출시)
- Jev는 텍스트를 생성하지 않고, 정해진 타입(예/아니오, 선택지, 점수)의 답과 확률·신뢰도만 반환하는 "System One" 모델임.
  따라서 풀이 설명 작성은 LLM이 맡고, Jev는 판단 역할만 맡기는 구조로 설계할 것.
- Jev 역할 후보:
  1. 업로드된 문제의 과목·단원·유형(객관식/주관식/계산) 분류 → 검색 범위 좁히기
  2. 객관식 정답 후보 선택 + 신뢰도
  3. LLM 풀이가 검색된 근거와 일치하는지 예/아니오 판정
  4. 신뢰도 기반 라우팅: 높으면 빠른 경로, 낮으면 강한 LLM으로 재풀이 또는 "확신 낮음" 표시
- 아직 모르는 것: 첫 결제가 필요한지, 대기자 명단 승인이 필요한지. TypeSafe 직접 API(api.typesafe.ai)와
  Cloudflare Workers AI(`typesafe/jev`) 두 경로가 있다고 알고 있음.
- 첫 작업으로 Jev 접근 방법·가격·가입 조건을 최신 자료로 확인해 줘. 그리고 Jev 없이도 전체 서비스가
  동작하도록 설계하고, Jev는 교체 가능한 모듈로 붙여 줘 (접근이 막혀도 프로젝트가 멈추지 않게).

## 인프라
- DB: AWS PostgreSQL + pgvector. 이전처럼 보안 그룹에 공인 IP를 등록해 권한을 주는 방식.
- 백엔드: FastAPI 선호. 프론트: React + Vite 선호.
- 이미지 업로드 문제는 OCR 또는 비전 LLM으로 텍스트·수식을 추출하는 단계가 필요함. 방식 비교해서 추천해 줘.
