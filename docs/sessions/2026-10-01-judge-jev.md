# 2026-10-01 판정기(Jev) 연결과 객관식 일관성 검사

## 무엇을 만들었나

**1. 판정기(Jev) — "답할 수 있나?"를 한 번 더 묻기**
질문을 검색하면 리랭커 점수에 따라 세 구간으로 나뉜다. 확실히 없음(확인 불가), 애매함(회색 구간), 확실히 있음(답변)이다. 이번에 애매한 회색 구간에서만 TypeSafe의 Jev에게 "이 근거들만으로 이 질문에 답할 수 있는가?"를 묻게 했다. Jev는 0~1 확률을 돌려준다. 0.5 미만이면 Gemini를 부르지 않고 "자료에서 확인 불가"로 답한다. 0.8 이상이면 "근거 확신 낮음" 표시를 뗀다. 그 사이면 답은 하되 확신 낮음 표시를 남긴다. 두 값은 잠정값이고 `.env`에서 바꾼다.

**2. 객관식 일관성 검사 — 답과 풀이가 서로 맞는지 코드로 확인**
객관식 답변은 보기마다 "①은 ~이므로 적절하다"처럼 한 줄씩 판단을 쓴다. 이 판단과 최종으로 고른 번호가 어긋나는지 코드로 검사한다. 예를 들어 "옳지 않은 것은?" 문제인데 '적절하지 않다'고 한 보기가 하나도 없거나, 고른 보기에 "근거에서 확인되지 않는다"고 써 놓은 경우다. 어긋나면 답을 지우지는 않고 "근거 확신 낮음"만 붙이고 이유를 기록한다.

**3. 기록**
판정 결과(확률, 걸린 시간, 토큰 수, 오류)와 객관식 검사 결과는 질문마다 `mingyu.query_logs.metadata`에 남는다. 나중에 데이터를 다시 넣고 기준값(0.5/0.8)을 다시 정할 때 이 확률값을 쓴다. `mingyu_app.judgments` 테이블은 어느 질문과 연결된 판정인지 가리킬 칸이 없어 이번에는 쓰지 않았다.

## 어떻게 돌아가나

1. `POST /qa`로 질문이 들어오면 `backend/app/qa/service.py`의 `answer_question`이 실행된다. 질문을 임베딩해 벡터로 후보 10개를 찾고, 리랭커로 다시 순위를 매겨 상위 5개를 근거로 고른다.
2. `backend/app/retrieval/search.py`의 `is_answerable`이 리랭커 1위 점수를 보고 구간을 정한다. 기준값은 `.env`의 `ANSWERABLE_MIN_RERANK_SCORE`(0.03), `ANSWERABLE_CONFIDENT_RERANK_SCORE`(0.15)다.
3. 회색 구간이고 판정기가 켜져 있으면(`JUDGE_PROVIDER=jev_typesafe`) `backend/app/judge/jev.py`의 `JevJudge.can_answer`가 Jev API에 요청을 보낸다.
   - 보내는 내용은 질문과 근거 5개(번호, 쪽, 제목 경로, 본문)다. 질문 문장은 `backend/app/prompts/judge_can_answer.json`에 있다.
   - 응답이 늦거나 429/529가 오면 몇 번 다시 시도한다. 그래도 실패하면 판정기가 없는 것처럼 동작한다(답변 + 확신 낮음).
4. `service.py`의 `judge_record`가 확률을 기준값과 비교한다. 0.5 미만이면 여기서 "자료에서 확인 불가"로 끝나고 Gemini를 부르지 않는다.
5. 답변을 만들면(Gemini) `backend/app/qa/mcq_check.py`의 `check_mcq`가 객관식인지 보고 일관성을 검사한다. 그 뒤 `low_confidence_reasons`가 확신 낮음 이유를 모은다.
6. 마지막으로 `_log`가 `mingyu.query_logs`에 한 행을 쓴다. `metadata.judge`, `metadata.mcq_check`, `metadata.low_confidence_reasons`, `metadata.timings_ms.judge_ms`가 이번에 추가된 칸이다.

이미 저장된 기출 실행 결과에 Gemini를 다시 부르지 않고 객관식 검사만 다시 돌리는 명령도 만들었다. `backend/app/qa/mcq_run.py`의 `check`이고, 결과는 `data/reports/mcq/{시각}.mcqcheck.md`에 저장된다.

## 아직 안 되는 것
- `.env`의 판정기는 꺼져 있다(`none`). 켤지는 결과를 보고 정한다.
- 0.5/0.8 기준값은 3문항으로만 확인한 잠정값이다. 팀원 정제 데이터로 다시 넣은 뒤 다시 정한다.

- `mingyu_app.judgments`에는 아직 기록하지 않는다(화면에서 풀이 저장을 만들 때 연결).
- 객관식 검사는 판정 이유와 결론이 맞는지 보지 않는다(예: "근거에 없으므로 적절하다"는 통과). p26-3처럼 근거가 있는데도 거절하는 문제도 그대로다.
- 화면(프론트엔드)은 아직 없다 → 다음 세션 첫 작업.
