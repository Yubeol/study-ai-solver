# 2026-09-30 리랭커 비교와 "확인 불가" 기준 정하기

## 무엇을 만들었나
- **리랭커 단계**: 벡터 검색은 질문과 청크를 따로 숫자(벡터)로 바꿔 비교하기 때문에, 말이 비슷하지만 뜻이 다른 청크가 위로 올라오는 일이 있었습니다. 리랭커는 질문과 청크를 **한 번에 같이 읽고** 관련도를 0~1 점수로 다시 매기는 모델입니다. 벡터 검색으로 후보 10개를 뽑고, 리랭커로 다시 줄 세운 뒤 상위 5개를 씁니다.
- **"확인 불가" 2단계 판단**: 교재에 없는 내용을 물으면 답을 지어내지 않고 "자료에서 확인 불가"라고 해야 합니다. ① 벡터 1위 점수가 0.45보다 낮으면 바로 확인 불가, ② 리랭커 1위 점수가 0.15보다 낮으면 확인 불가로 판단합니다. 두 값은 질문 33개로 잰 **잠정값**입니다.
- **평가 스크립트 확장**: 기존 검색 평가에 리랭커를 켜고 끄거나 모델·후보 수·입력 텍스트를 바꿔 가며 비교하는 옵션, 리랭커 점수 분포, 질문당 리랭크 시간을 추가했습니다. 두 후보 모델(`BAAI/bge-reranker-v2-m3`, 한국어 미세조정판 `dragonkue/bge-reranker-v2-m3-ko`)을 비교해 앞의 것을 골랐습니다.

## 어떻게 돌아가나
1. 질문이 들어오면 `backend/app/retrieval/search.py`에서 BGE-M3로 질문을 벡터로 바꾸고, `search_theory`가 DB의 `mingyu.v_searchable_theory`(검색 가능한 이론 청크)에서 가장 가까운 청크 `SEARCH_CANDIDATES_N`(10)개를 가져옵니다. 이때 청크의 `embedding_text`(제목 경로 + 본문)도 함께 가져옵니다.
2. `.env`의 `RERANKER_MODEL`이 비어 있지 않으면 `backend/app/retrieval/rerank.py`의 `get_reranker`가 리랭커 모델을 불러옵니다(처음 한 번만, 모델 파일은 `E:\hf_models`). `rerank` 함수가 (질문, 청크 글) 쌍 10개에 점수를 매기고 점수 높은 순으로 다시 정렬합니다. 각 결과에는 원래 벡터 순위·벡터 점수·리랭커 점수가 같이 붙습니다.
3. `search.py`의 `is_answerable`이 벡터 1위 점수와 리랭커 1위 점수를 `.env`의 `ANSWERABLE_MIN_VECTOR_SCORE`(0.45), `ANSWERABLE_MIN_RERANK_SCORE`(0.15)와 비교해 "답변 시도" 또는 "확인 불가"와 그 이유를 돌려줍니다. 지금은 명령줄 검색에서 결과만 보여 주고, 답변 생성과 연결하는 것은 다음 세션입니다.
4. 평가(`backend/app/retrieval/evaluate.py`)는 질문 33개(`data/eval/questions.csv`)를 먼저 모두 벡터 검색한 뒤, **메모리를 아끼려고 임베딩 모델을 내리고** 리랭커를 올려 리랭크합니다. 결과는 `data/reports/eval/{시각}.json/.txt/.html`에 저장되고(DB에는 아무것도 쓰지 않음), HTML 보고서에는 리랭크 전 벡터 순위도 함께 표시됩니다.

결과 요약: 벡터만 쓸 때 1위 적중 81% → 리랭커 후 85%(3과목은 60% → 90%). 자료에 없는 질문 7개는 모두 "확인 불가"로 막히고, 답할 수 있는 질문 26개 중 24개는 통과합니다. 한국어판(-ko)은 순위는 더 좋았지만(92%) 정답에도 0점 가까운 점수를 줘서 "확인 불가" 기준으로 쓸 수 없어 제외했습니다. 자세한 표는 `docs/DECISIONS.md`의 D-024에 있습니다.

## 직접 확인하는 방법
PowerShell에서 실행합니다(모델 로딩 때문에 처음 몇십 초 걸림).

1. 리랭커를 켠 검색:
   ```powershell
   cd E:\자료실\adsp-study-rag\backend
   uv run python -m app.retrieval.search "의사결정나무에서 지니 지수는 뭐야?"
   ```
   기대 결과: 둘째 줄에 `리랭커: BAAI/bge-reranker-v2-m3 / 판단: 답변 시도(ok)`, 각 결과에 `[리랭커 점수] (벡터 N위 벡터 점수)`가 표시됩니다.
2. 교재에 없는 질문:
   ```powershell
   uv run python -m app.retrieval.search "트랜스포머의 셀프 어텐션은 어떻게 동작해?"
   ```
   기대 결과: `판단: 확인 불가(rerank_below_threshold)` 또는 `확인 불가(vector_below_floor)`.
3. 리랭커 없이 비교: 같은 명령 끝에 `--no-rerank`를 붙이면 벡터 순위만 나옵니다.
4. 평가 다시 돌리기(약 5분, 질문당 리랭크 약 6초):
   ```powershell
   uv run python -m app.retrieval.evaluate
   ```
   기대 결과: `hit@1 22/26(85%)`, `리랭크 시간(질문당, 초): 평균 약 6`, 리랭커 임계값 표의 `0.15` 줄이 `24/26 … 7/7`. 벡터만 보려면 `--reranker none`, 다른 모델은 `--reranker dragonkue/bge-reranker-v2-m3-ko --n 20`.
5. 보고서: `E:\자료실\adsp-study-rag\data\reports\eval\20260930-205236.html`을 브라우저로 열면 질문별 상위 5개 청크(리랭커 점수 + 벡터 순위)와 페이지 썸네일을 볼 수 있습니다.
6. 실제 리랭커 모델 테스트: 저장소 루트에서 `uv run pytest -m reranker_model` → `1 passed`.

## 아직 안 되는 것
- 검색 결과로 답변을 만드는 질의 흐름(API, 답변 생성, 근거 일치 판정)과 판정기(Jev)는 다음 세션입니다.
- "확인 불가" 기준값(0.45 / 0.15)은 Claude가 만든 질문 33개로 잰 잠정값입니다. 실제로 써 보며 다시 재야 합니다.
- 정답이 1위인데도 리랭커 점수가 낮아 "확인 불가"가 되는 질문이 2개 있습니다(c06 시계열 정상화, c09 향상도). 그래서 세션 끝에 **3구간 방식으로 바꾸기로 설계만** 해 두었습니다: 리랭커 점수 0.03 미만은 바로 "확인 불가", 0.03~0.15는 회색 구간(판정기에게 묻거나, 판정기가 없으면 답하되 "근거 확신 낮음" 표시), 0.15 이상은 그대로 답변. 지금 코드는 아직 0.15 하나로 자르는 방식이고, 3구간은 다음 세션(질의 흐름) 때 구현합니다.
- 원인으로 보이는 "표·수식이 한 줄로 뭉친 청크"(c06·c07·c09) 개선은 질의 흐름 다음 작업으로 잡아 두었습니다.
- 리랭커 입력 최대 길이 512와 1024 비교는 하지 않았습니다(다음 세션의 서버 메모리·응답 시간 측정 때 함께).
- 리랭크가 CPU에서 질문당 평균 6초(최대 10초) 걸립니다. 서버에서 임베딩 모델과 리랭커를 동시에 올릴 때의 메모리 사용량은 아직 재지 않았습니다.
