# 2026-10-01 최소 공부 화면 + 판정기(Jev) 켜기

## 무엇을 만들었나
- **최소 공부 화면**: 브라우저에서 질문을 입력하면 답변과 근거(교재 원문)를 보여 주는 한 화면이다. 지금까지는 `/qa` API를 명령으로만 불렀는데, 이제 화면에서 바로 공부 질문을 해 볼 수 있다.
- **객관식 표시**: 객관식 문제를 넣으면 "정답은 ③이다"를 강조 상자로 따로 보여 주고, 보기 ①~④에 대한 판단을 한 줄씩 나눠 보여 준다. 판단과 고른 번호가 어긋나면 "근거 확신 낮음"과 그 이유를 사람이 읽는 문장으로 보여 준다.
- **판정기(Jev) 켜기**: `.env`의 `JUDGE_PROVIDER`를 `jev_typesafe`로 바꿨다. 이제 근거가 애매한 질문(회색 구간)은 판정기가 "근거로 답할 수 있는지" 확률을 매겨, 낮으면 "자료에서 확인 불가"로 답한다.

## 어떻게 돌아가나
1. 화면(`frontend/`)은 Vite 개발 서버(http://localhost:5173)에서 열린다. 백엔드에는 다른 주소에서 오는 요청을 허락하는 설정(CORS)이 없다. 그래서 개발 서버가 `/qa`, `/subjects` 요청을 받아 백엔드(기본 http://127.0.0.1:8000)로 대신 넘긴다(`frontend/vite.config.ts`, 주소는 `frontend/.env`의 `VITE_API_TARGET`).
2. 화면이 열리면 `components/SourceSelector.tsx`가 `api.ts`의 `getSubjects()`로 `GET /subjects`를 불러 과목 목록을 채운다. 지금 `/qa`에는 과목을 고르는 기능이 없으므로, 고른 값은 서버에 보내지 않고 화면에만 들고 있다. 나중에 "업로드한 자료 선택"으로 바꿀 때 이 파일만 교체하면 된다.
3. 질문을 쓰고 [질문]을 누르면(`components/QuestionForm.tsx`) `App.tsx`가 `api.ts`의 `ask()`로 `POST /qa`를 보낸다. 기다리는 동안 버튼이 꺼지고 경과 초가 표시된다. 60초(`VITE_QA_TIMEOUT_SECONDS`)가 지나면 요청을 끊고 "응답 시간이 초과됐습니다"를 띄운다. 백엔드가 꺼져 있으면 개발 서버가 빈 502를 돌려주므로 "서버에 연결할 수 없습니다(백엔드 실행 확인)"를 띄운다.
4. 백엔드는 이전과 같다(`app/qa/service.py`의 `answer_question`). 검색, 리랭크, "확인 불가" 3구간 판단을 거친다. 회색 구간이면 판정기(`app/judge/jev.py`)를 부르고, 그다음 Gemini로 답변을 만들어 인용을 검사한다. 객관식이면 보기 판단과 고른 번호가 맞는지 검사(`app/qa/mcq_check.py`)한 뒤 `query_logs`에 기록하고 결과를 돌려준다. 이번 세션에서 백엔드 코드는 바꾸지 않았다.
5. 응답이 오면 화면이 나눠서 보여 준다.
   - `components/AnswerView.tsx`: 답, 설명, 헷갈리는 점. 객관식이면 `src/text.ts`의 `splitOptionLines`가 설명 문단을 ①~④ 줄로 나눈다(백엔드 검사와 같은 규칙이고, 내용은 바꾸지 않는다).
   - `components/ConfidenceNotice.tsx`: 확신 낮음 이유 코드를 문장으로 바꾼다.
   - `components/CitationList.tsx`: 인용된 근거의 교재 원문 카드. 본문의 [n]을 누르면 해당 카드로 이동한다(`CitedText.tsx`).
   - `components/DevInfo.tsx`: 개발 확인용 작은 회색 글씨(구간, 점수, 판정기 확률, 단계별 시간, query_log 번호).
6. 저장되는 곳은 이전과 같이 DB의 `mingyu_app.query_logs`뿐이다. 판정기 결과는 그 행의 `metadata.judge`에 들어간다.

## 직접 확인하는 방법
1. 백엔드 실행: PowerShell에서 `cd E:\자료실\adsp-study-rag\backend; uv run uvicorn app.main:app --reload`를 실행한다. 모델 로드에 약 1분 걸리고, "Application startup complete"가 나오면 준비된 것이다.
2. 화면 실행: 새 PowerShell 창에서 `cd E:\자료실\adsp-study-rag\frontend; npm run dev`를 실행한다. 처음 한 번은 `npm install`과 `copy .env.example .env`가 필요하다(이미 해 둠).
3. 브라우저로 http://localhost:5173 을 연다. 과목 칸에 "ADsP"가 보이면 연결된 것이다.
4. 질문을 넣고 결과를 확인한다(Gemini 한도 때문에 몇 개만).
   - "시계열 평균이 계속 올라가는 추세가 있으면 모형 만들기 전에 뭘 해줘야 해?" → 답변과 247쪽 근거가 나온다. 아래 회색 글씨에 "판정기 jev_typesafe · 확률 0.9x"가 보인다.
   - "Mean Shift 군집은 군집 개수를 미리 안 정해도 된다던데 어떻게 군집을 찾는 거야?" → "자료에서 확인 불가". 판정기 확률이 0.05 정도로 보인다.
   - 객관식 문제(문제 + ①~④ 보기 4줄)를 넣는다 → "정답은 …" 상자와 보기별 판단 줄이 나온다. 판단이 어긋나면 노란 "근거 확신 낮음" 상자에 이유가 나온다.
5. 오류 문구 확인: 백엔드 창을 Ctrl+C로 끄고 질문하면 빨간 상자에 "서버에 연결할 수 없습니다(백엔드 실행 확인)"가 나온다.
6. DataGrip: `mingyu_app.query_logs`의 최근 행에서 `metadata` → `judge.probability`(회색 구간 질문일 때)를 확인한다.

## 아직 안 되는 것
- 답변 피드백(좋음/틀림, 메모) 저장, 검수 탭, 이론 보충 입력. 피드백 저장 위치는 다음 세션에서 정한다.
- 상단바, 사이드바, 업로드 탭 같은 전체 화면 구성(팀과 정한 뒤 만든다).
- 과목(나중에는 자료) 선택값으로 검색 범위를 좁히는 것(`/qa`에 필터가 없음).
- 문제 사진 입력, 제약 프리셋, 시각자료(crop 이미지) 근거 표시.
- 화면은 개발 서버(`npm run dev`)로만 띄운다. 빌드 결과를 백엔드에서 서빙하는 방식은 아직 정하지 않았다.
- 판정기 기준값 0.5/0.8과 "확인 불가" 기준값은 잠정값이다. 팀원 정제 데이터로 재적재한 뒤 다시 잡는다.
